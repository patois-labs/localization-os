# Local test envs: install alongside the runtime deps (plain requirements.txt,
# no hashes) in ONE call:
#     pip install -r requirements.txt -r requirements-dev.txt
#     pytest -q
# A hash anywhere arms pip's require-hashes mode for the whole call (GitHub #403),
# so never mix this unpinned file with a hashed lock in one pip call.
#
# CI installs the test toolchain hash-pinned from the generated requirements-dev.lock
# (GitHub #412), never this unpinned file:
#     pip install --require-hashes --no-deps -r requirements.lock -r requirements-dev.lock
# For local runs prefer the same hashed install; the unpinned form above is only for trying a bump.
# Regenerate the lock after changing the pins below (network; review the diff), from the repo
# root, as ONE command line:
#     uv pip compile requirements-dev.txt --universal --python-version 3.13 --no-header
#         -c requirements.lock -c requirements-saml.lock -c requirements-postgres.lock
#         -c requirements-ldap.lock -o requirements-dev.lock
# then re-add the provenance header and run scripts/hash_locks.py (adds the SHA256s).
# Same flow for scripts/locks/requirements-ci-check-tools.lock (pytest + packaging subset).
# The lines below stay the human-curated DIRECT pins.
#
# `pytest -q` runs tests/test_verify_suites.py, which spawns each of the 418
# tests/verify_*.py suites as its own subprocess, ~13s apiece. A full run is
# therefore ~90 MINUTES, not a few minutes -- budget for that or run a narrow
# selection instead:
#     pytest tests/test_verify_suites.py -k "<name>"
# Verify what a selection actually collected before trusting a green run
# (a `-k` filter is substring match, not a gate).
