Data retention

Automatically delete aged uploads, documents, and finished jobs after a retention window. Destructive and irreversible - off by default. A window of 0 days never deletes anything.

Deleting an aged document takes everything hanging off it: its segments and upload file, its full workflow-run history (runs, step traces, fan-out batches), its LQA results, post-edit episodes and query threads, and any vendor dispatch leg anchored to those runs - including a frozen operator-delivery package it holds.

Translation memory also ages out row by row. TM recently approved, updated or used, and TM matching surviving document segments, is kept. Internal key-project catalogues and their TM are exempt. Other TM older than the window, including imported reference TM, is deleted. Ordinary uploads in key projects follow the same retention rules as other uploads. The same TM aging rules apply when a project has no documents left.

Kept, with only their link to the deleted rows cleared: term candidates (document/segment/run provenance stripped), and delivery-empty approvals that are not the deleted document's (their run link cleared, the approval itself intact). One effect reaches outside the deleted set: a surviving document's QA findings or post-edit episodes lose their vendor-leg attribution if they reference a dispatch leg the sweep erases.

How switching a feature off works, in full

For the removal-semantics majority, disabling a feature removes it rather than hiding it: its pages and API routes answer not found (indistinguishable from a route that was never built, so they can't be discovered by probing), its CLI verbs refuse naming the switch, and its MCP tool stays listed but refuses when called. A few modules ship off by default as opt-ins (each card says which). Existing data is always kept and returns when you switch a feature back on.

The enterprise turn-on features - SAML SSO, SCIM provisioning, OpenTelemetry, Prometheus /metrics, PII named-entity redaction, the durable job queue and S3 storage - are managed on the dedicated Enterprise features panel (with a preflight and an operator-key step-up), not here.
