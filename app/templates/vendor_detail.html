Dispatch options

Fine-tune what a dispatch to this vendor carries. Every dispatched segment is still packaged and its id still returns; these options only shape the payload.

{% include "_csrf.html" %} {% set field_label_4 %}Dispatch options{% endset %} {% call m.form_section("vendor_detail-fields-4", field_label_4) %}

When on, a locked segment (100% TM / context / repetition) ships its source + a locked marker but an empty target - the vendor never receives the leveraged text. Off (default): the leveraged target ships, visible-but-locked.

Wave E R3: when on, a dispatch to this vendor parks QUOTED and awaits a quote (recorded here or submitted over the wire) and then an operator approval before work proceeds and any return is admitted. Off (default): dispatch parks DISPATCHED and the vendor may begin immediately. Only enable this for a vendor whose system implements POST /webhooks/vendor-quotes (or whose operator records the quote here manually); a vendor that ignores quote_requested and simply delivers will have its delivery refused until the quote is approved.

Open dispatches

Work this vendor is holding. A return normally arrives on its own (the signed callback, or a poll when the vendor exposes one); this panel is the manual fallback. A leg tagged manual delivery has no wire at all - nothing was sent: download its XLIFF, hand it to the vendor out-of-band, and the return comes back through the upload box below. However it arrives, the payload is judged identically: every dispatched segment id must come back exactly once, and every returned string goes through the same guarded write seam as a machine translation - tags, glossary/DNT, language, number and refusal checks all apply. A conversational refusal or a hard TM lock WITHHOLDS the text (nothing is stored, the segment is routed to review); the softer lanes (glossary/DNT/language/number/length/tag) STORE the text and then flag the segment needs_review. A return that just echoes the source is treated as “not translated” and never overwrites an existing translation.

Delivered (reworkable)

Recently returned work. If a delivery is not good enough, reject it to re-dispatch a rework round to this same vendor, carrying structured feedback (which segments failed which guard lanes + your note). Rework rounds are capped (vendor_rework_max_rounds, default 1, settable from 1 to 10); past the cap a reject escalates to a human instead. A rework never injects content - its return still goes through the one guarded admission seam.
