Import CSV or TBX

CSV columns: source_term, target_term, dnt, sense_label, context_cue, part_of_speech, definition, usage_example, subject_field, notes. The last five are optional - an older CSV without them still imports. Export includes them all.

A .tbx termbase (TBX 2.0/martif or TBX-Basic v3 DCA) imports for the locale pair below: source/target terms, part of speech, definition, subject field and the Do-Not-Translate flag. It takes the flat import (one entry per matching pair). Concept-preserving TBX import is reserved: it arrives with the terminology authority train, so ticking it is refused for now, pointing you at the standard import (a .glossary.json round-trip carries the concept store losslessly meanwhile). Tick Strict to refuse the whole import on the first TBX-Basic conformance finding. A base-language termbase (e.g. xml:lang="es") projects onto a regional pair (es-ES) by base language; a termbase whose languages match no configured pair imports 0 entries and reports them as skipped (the flat entry import never refuses on a language mismatch).

TBX export defaults to TBX-Basic v3 (DCA): house fields with no standard data category (DNT, audience, status, case-sensitivity, exact-match, out-of-picklist categories, subdomain, usage note) ride a documented private namespace (los:). Portable drops the los: fields and emits a clean pure-TBX-Basic instance that validates with zero findings (lossy - the download names every field type it drops). The .glossary.json export is the no-caveat lossless format.
