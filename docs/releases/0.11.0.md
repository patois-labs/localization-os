# Localization OS 0.11.0

> Pre-open-source history. These notes describe a release from before Localization OS became open source; some features mentioned here (Advanced Workflows, evaluations, memory, Databricks export) are now paid add-ons and are not part of this repository.

Release date: October 13, 2026. Previous release: 0.10.0 (October 8, 2026). Release 0.11.0 is what
production runs since the October 13 deploy; it covers two deploys, October 12 and October 13. Until
the next build, the app reports this version as `v0.11.0-89-g24c084909`.

Release 0.11.0 is about reach and hands-off operation. Localization OS now reads and writes about 85 file
formats (up from 11), connects to 28 content systems (up from 8 open for new connections), and its MCP
server for AI agents was reviewed end to end against the current MCP specification. Every new format
was run through a large test corpus in 19 target languages before release, and the problems that test
found were fixed. The October 13 deploy adds project automation (a project pulls from and writes back to
a connection on a schedule), notifications to Slack, Microsoft Teams, a signed webhook or email, and
custom project fields. All three are off until someone sets them up: an upgraded install has no
automations, no notification channels and no custom fields defined.

## Highlights

1. **Project automation.** Bind a project to a connection as the place its content comes from and goes
   back to, then let it run on a schedule (times of day on chosen days, or every N minutes), or press
   Run now. Budgets, an optional per-run spend cap, automatic pause after repeated failures and a run
   history keep it in check. One connection can feed many projects without two projects ever writing
   the same item and language.
2. **Notifications.** Projects post run results, review waits, limits and pauses to Slack, Microsoft
   Teams, a signed webhook or email. Messages carry counts, project names and a status link, never
   your content.
3. **Custom project fields.** Add your own fields to projects (text, numbers, dates, choices, links, and
   external links such as a Jira ticket), show them as columns in the project list, and filter and sort
   by them.
4. **About 85 file formats.** Office (Word, Excel, PowerPoint, Visio, OpenDocument), desktop
   publishing (InDesign IDML, InCopy ICML, FrameMaker MIF, QuarkXPress Tags, MadCap Flare), help and
   documentation formats (DITA, DocBook, AsciiDoc, reStructuredText, LaTeX, MDX, wiki markup, HTML
   Help, EPUB), subtitles and broadcast captions, software resource files for every major platform,
   and the bilingual files of the common CAT tools (Trados, memoQ, Phrase, Wordfast, WorldServer).
   Upload a ZIP to add many files at once.
5. **28 connectors.** New: GitHub, GitLab and Bitbucket (one pull or merge request per run),
   Microsoft 365 Files (SharePoint and OneDrive), Google Docs, Sanity, Sitecore XM Cloud, ServiceNow
   Knowledge, Plytix, Drupal (experimental) and CMS via MCP (a prototype that drives any CMS through
   that CMS's own MCP server). Rebuilt and open again for new connections: Confluence, Zendesk Guide,
   Document360, Freshdesk, Zoho Desk, Intercom, Salesforce Knowledge, Notion and Help Scout Docs.
6. **Files come back the way they went in.** A language with nothing translated yet exports your
   original file byte for byte. Translated files keep their byte-order mark, line endings and, for
   text formats, their code page when the translation fits.
7. **Right-to-left layout.** Arabic, Hebrew, Persian and Urdu targets get right-to-left sheets in
   Excel and OpenDocument, right-to-left paragraphs with the World-Ready composer in InDesign and
   InCopy, and right-to-left text in Visio, SVG and TTML captions.
8. **Fewer wrong translations reach your users.** New review holds catch ambiguous numeric dates,
   added or lost line breaks and words glued together at a formatting change. Placeholders that name
   their argument may change order, as languages need, while dropped or added ones are still held.
9. **A safer MCP server for AI agents.** Spending needs a confirmed plan, slow work runs in the
   background with a job id, text from outside the app is marked as data, the tool list follows the
   key's permissions, and people can connect by signing in (off by default).

## What's new by area

### Project automation (October 13)

- **A project's content source.** Open a project and choose Automation. Pick a connection as the
  place the project pulls content from and writes translations back to, with an optional project
  scope. Administrators can also create a connection and bind it in one API call.
- **Schedules.** Times of day on chosen days of the week, or every N minutes (15 minutes to 7 days).
  Schedule times are UTC; the Automation page shows your local time beside each one. Each schedule
  runs in delta mode (only new or changed content) or full mode (everything again; translation memory
  matches cost nothing, anything else is translated and paid for). A full pull still respects the
  review gate, draft versus live settings, protection of edits made in the source system and the
  per-run write limit, and walks a large scope over several runs.
- **Run now, pause and resume** on the same page. Turning a schedule on never starts a run at once. A
  run started while one is in progress hands back the run already going.
- **Nothing spends by surprise.** The project's budget is checked when a run is queued and again when
  it starts, and an optional per-run spend cap stops a run at that amount (there is no default cap). A
  run stopped by the cap or the budget counts as a partial run, not a failure. After three failed runs
  in a row (configurable) the schedule pauses itself; a connection that needs to be reconnected pauses
  it at once.
- **Run history** lists when each run happened, why (schedule, catch-up, run now), the mode, and what it
  wrote, held for review or failed. Cost is shown to managers and administrators only.
- **One connection, many projects.** When a connection already feeds a project, the next project gets
  its own private copy (same credential, kept in step, its own tracking). The first project to reach an
  item in a language owns that item and language; a later project skips it and its run is marked
  blocked, so two projects never overwrite each other. Both projects are notified once, and a manager
  or administrator can hand the items over to the other project with one click. Ownership is released
  when a project is archived or unbound, or when the item leaves the project's scope.
- **After downtime** the missed scheduled runs are made up by one catch-up run, then the project is
  back on its normal schedule. The run history marks it.
- **Organization-wide connections.** A manager can bind a connection saved for the whole organization to
  a customer's project; it always runs on the project's own copy, so the shared connection never
  changes.
- **Every surface.** Web (project Automation page), API (`/api/projects/{id}/automation`, `/source`,
  `/runs`), CLI (`project bind`, `unbind`, `automation show|set|pause|resume|handover`, `run`, `runs`)
  and MCP (`project_automation`, and `project_run`, a spend tool: plan, then confirm). Over MCP an agent
  cannot turn a schedule on, resume it, switch to full mode, change its times or raise the spend cap.

### Notifications (October 13)

- **Channels:** Slack (incoming webhook), Microsoft Teams, a signed webhook (HMAC
  signature; the signing secret is shown once) and email. Add them under Settings > Notifications.
- **Events:** a run finished, failed, is waiting for review, or hit a limit (budget, write limit or
  spend cap); automation paused or blocked by another project; and, when you choose them, a run
  started, a project created and a project completed.
- **Routing:** attach a channel to a project, content type, project type, customer or the whole
  organization; for each kind of channel the most specific level wins, and a project can be muted. Each message is sent once per
  channel and event.
- **Status links only.** Messages carry counts, project names and a link to the project. They never
  include your content, error text or cost.
- **Delivery log** with automatic retries (after 1, 5 and 30 minutes), retry of failed deliveries and a
  test send.
- **Who can do what:** managers and administrators create channels and attach them to projects,
  customers and types. Only the person who created a channel, or an administrator, can edit, re-point
  or delete it, and only administrators attach or remove organization-wide channels. Changing a
  channel's address or secret is audited and e-mailed to the administrators.
- Web, API (`/api/notify/...`), CLI (`notify channel|route|project`) and MCP (`project_notifications`:
  list, show, attach, mute and unmute; an agent cannot create or delete a channel or read its address).

### Custom project fields (October 13)

- **Field types:** text, long text, number, date, select, link, and external link (a link with a key
  and label, for example a Jira ticket; paste a Jira link and the key is read from it).
- **Where they show:** the project page header and an edit form, the New project dialog, and the
  project list, where fields can be default columns, each person can pick their own columns, and you
  can filter and sort by a field.
- **Who defines them:** administrators define fields for the whole organization or for one customer;
  managers define fields for a customer. A manager changes or archives only the fields it created.
  Values are set by anyone who can edit the project.
- Only `https://` links are stored and shown. Every change is audited.
- Web (Manage custom fields on the Projects page), API (`/api/custom-fields`, `/api/projects/{id}/fields`, and field
  filters and sorting on `GET /api/projects`), CLI (`field list|create|update|archive|restore`,
  `project set-field`, `--field` on project create and list) and MCP (`manage_custom_fields`,
  `set_project_fields`, and field filters on `list_projects`).

### Fixes (October 13)

- A percent sign glued to a word in marketing text (20%OFF, 50%Rabatt) is no longer read as a
  placeholder, while a dropped or added duplicate placeholder is still caught.
- The editor keeps a segment's translation memory label when you save it without changing it.
- `engine create` and `engine update` in the CLI accept `--secret api_key=-` to read the key from
  standard input, so it never appears on the command line or in shell history. An empty line is refused.
- Term extraction with an engine that is not available returns a clear error (`engine_unavailable`)
  instead of failing.
- A link whose only change is the locale (for example `/en/` to `/fr/`, `en-us` to `fr-fr`, or a
  `?lang=` value) no longer holds the segment for review. Any other change to a link is still held.
- The Automation page labels the next-run time in your local time zone as local.

### File formats

- **Office and documents:** PowerPoint (.pptx and its macro and template forms), OpenDocument text,
  spreadsheets, presentations and drawings, Visio (.vsdx, .vsdm), EPUB 2 and 3, e-mail messages
  (.eml) and Strict Open XML Word, Excel and PowerPoint files.
- **Excel:** the translation is written into your own workbook, so text boxes, shapes, EMF and WMF
  pictures, charts, comments, data validation and printer settings come back as uploaded. Text in
  text boxes and shapes is now translated (re-import an older workbook to get it).
- **Word:** text inside nested smart tags, hyperlinks inside tracked changes and inline content
  controls is translated for documents uploaded from this release on.
- **Comments:** a per-project "Translate comments" option (off for new projects) offers Word, Excel,
  PowerPoint, OpenDocument and Visio comments for translation. Projects created before this release
  keep translating Word comments.
- **Desktop publishing:** InDesign IDML, InCopy ICML and WoodWing WCML, FrameMaker MIF, QuarkXPress
  Tags and MadCap Flare project archives, each returned in its own format with untouched parts byte
  for byte.
- **Documentation and web:** generic XML with W3C ITS 2.0 rules, DITA, DocBook, multilingual XML,
  AsciiDoc, reStructuredText, LaTeX, MDX, MediaWiki and DokuWiki, XSLT, server-page templates (PHP,
  JSP, ASP.NET, ERB, server-side includes), Microsoft HTML Help and Markdown front matter (only text
  values are translated).
- **Subtitles and captions:** YouTube SBV, SubViewer, MicroDVD, SSA/ASS, TTML/DFXP, Scenarist SCC
  and EBU STL, alongside SRT and WebVTT.
- **Software resources:** Java .properties, Apple .strings, .stringsdict, .xcstrings, .plist and
  Xcode .xcloc, Android strings.xml, .NET RESX/RESW, XAML, WiX, Qt .ts, Windows .rc, INI, RESJSON,
  YAML, TOML, JSON5, Flutter ARB and other JSON message dialects, PHP arrays, JavaScript and
  TypeScript message modules, Mozilla DTD and Fluent, compiled gettext .mo, Angular XMB/XTB,
  .desktop files, Haiku catalogs and Salesforce Translation Workbench .stf. Key projects can import
  and export these resource formats too.
- **CAT tool files:** Trados SDLXLIFF, project packages in (.sdlppx) and return packages out
  (.sdlrpx), TagEditor TTX, memoQ MQXLIFF and MQXLZ, Phrase MXLIFF, Wordfast TXML and TXLF, and
  WorldServer XLZ. A bilingual file is translated only into the target language it declares; a
  mismatch is a warning, or a refusal when no project language matches.
- **Terminology and memory:** glossary import from MultiTerm XML and TBX (2002, Basic and v3),
  spreadsheet glossaries and memories (.xlsx, .csv, .tsv), and Trados Studio .sdltm memories.
- **Other:** AutoCAD DXF (ASCII), CSV/TSV with a column mapping, SVG titles and descriptions
  (screen-reader text), and more raster image types for image localization (.tif, .bmp, .gif, .webp).
- **Encodings:** a text file in a legacy code page that declares none is read in the code page of the
  project's source language, with a warning when the letters look wrong.
- **Plural forms:** gettext, i18next, Qt, Rails YAML, Fluent and ARB exports fill the plural forms a
  target language needs (Polish, Russian, Arabic and others) with the plural translation instead of
  leaving them empty.
- **Sentence splitting:** the built-in splitter no longer breaks after common abbreviations (e.g.,
  incl., Mr., Dr., z. B. and others). Documents imported earlier keep their split.

### Translation quality

- Review holds for ambiguous numeric dates, line breaks that differ from the source, and (in German,
  Dutch, Finnish, Korean, Turkish, Arabic and Hebrew) words glued together at a formatting change.
  A held translation is kept out of translation memory until a person saves or approves it, and the
  export still writes it.
- Named placeholders (%1$s, {name}, %(name)s) may change order; Python %(name)s is protected.
- Stronger placeholder checks: ICU plural and select structure, brace balance, printf length
  modifiers, Qt %1 to %99, escaped percent signs, HTML tags in resource strings and ICU number and
  date styles the engine translated.
- Segments with no translatable text (only tags or numbers) are copied, never sent to the engine.
- A very long segment is translated in pieces instead of failing on the engine's output limit, and a
  runaway generation is stopped early.
- A translation that echoes the prompt's labels is cleaned, and the longest glossary match wins when
  terms overlap.

### Connectors

- See Highlights for the new and rebuilt connectors. All of them follow the same rules: a unit held
  for review is never written to the source system as a translation, draft modes never change live
  content, edits made by hand in the source system are kept, and every write stays inside the
  connection's configured scope.
- Contentful Rich Text fields are translated; HubSpot connects with Service Keys; Shopify uses
  client-credential sign-in and the 2026-10 Admin API; Jira keeps comment formatting and writes only
  the configured target field; Strapi skips fields marked not localized.
- Jira JQL and Confluence space and CQL scopes can be changed only by an administrator once a
  connection holds a saved credential, as for Airtable, ServiceNow and Notion.

### MCP server, API and CLI

- Every tool has a title, permission annotations, structured output and machine-readable error codes.
- Spend tools return a plan with a `plan_id`; the confirmed call must carry that `plan_id` with the
  same arguments within 30 minutes. An optional setting asks the person to approve each spend in
  agent hosts that support it.
- Slow tools (connector syncs, Advanced missions, term extraction, image translation, evaluations)
  start in the background and return a job id; `job_status` shows the result. An optional
  idempotency key prevents double spending when a call is sent twice.
- Text from outside the app in tool results is marked as data, and connector results say that
  publishing in the source system is the person's decision.
- The tool list shows only what the key's scopes allow, and operators can load named toolsets.
- A local MCP server reads files only from your Documents and Downloads folders (or folders you
  configure).
- MCP sign-in with OAuth 2.1 (off by default): people connect apps such as claude.ai or ChatGPT
  connectors with their normal sign-in and a consent page, and manage them under Account > Connected
  apps.
- On the API, billing routes accept `Prefer: respond-async` and an `Idempotency-Key` header, and
  `GET /api/account` reports the calling key's scopes.

### Reliability

- Long work started from the web or API (Advanced missions, memory distillation, evaluations, A/B
  tests, engine checks and query e-mails) no longer blocks other requests while it runs.

## Security improvements

- Notification channels send only over HTTPS through one guarded client: no redirects, private and
  local addresses refused, Slack and Teams addresses pinned to their own hosts, webhook ports limited
  to 443 and 8443. Channel addresses and signing secrets are encrypted at rest and never shown again.
- Custom field patterns are checked before they are saved, so a pattern cannot make a check run for
  a long time, and only `https://` links are stored or shown.
- An automation run that could not read every item keeps its claims on the items it missed, so another
  project cannot take them over by mistake.
- A translated HTML attribute on a malformed page can no longer add markup or an event handler.
- GitHub, GitLab and Bitbucket refuse to overwrite executable or Git LFS files.
- New file parsers are bounded against oversized archives, entity expansion and slow regular
  expressions, and e-mail export cannot inject MIME boundaries.
- MCP OAuth tokens are bound to the MCP server's address, dynamic client registration is off unless
  turned on, and administration is never grantable to an app.

## Changed or removed

- **Placeholder and link checks:** text such as 20%OFF is no longer flagged as a placeholder, and a
  link that changes only its locale is no longer held (see Fixes).
- **A connection used by a project automation** no longer runs its own interval schedule; move the
  schedule to the project.
- **MCP spend confirmations need the `plan_id`.** A script or agent that confirms a spend without
  first asking for a plan now gets `spend_refused`. Ask for the plan, then confirm with its `plan_id`.
- **The MCP tool list follows the key.** A key without the `keys` scope no longer sees the key tools,
  and so on. Set `LOC_STUDIO_MCP_SCOPE_FILTER=off` on the MCP server to list every tool.
- **Local MCP file access is limited** to your Documents and Downloads folders and your OneDrive
  Documents folder (or, when `LOC_STUDIO_INPUT_DIRS` is set, only the folders it names), plus the
  output folder.
- **Comments in Office files** are off by default for new projects (see File formats).
- **Legacy-encoded text files** are no longer always exported as UTF-8: they keep their code page
  when the translation fits.

## Upgrade notes for self-hosted installs

- Five database migrations run at startup, all new tables or columns: MCP OAuth grants (October 12),
  then custom project fields, notification channels, project automation and automation hand-over
  (October 13).
- New settings for the October 13 features, each on by default and acting only once something is set
  up: `project_automation_enabled`, `notify_outbound_enabled` and `custom_fields_enabled` (also the
  `custom_fields` module). Turn one off to stop that feature; stored data is kept. Scheduled
  automation runs also stop when the install-wide scheduler switch is off.
- The MCP server now has 89 tools (5 new: `project_automation`, `project_run`,
  `project_notifications`, `manage_custom_fields`, `set_project_fields`).
- New dependency: `fluent.syntax` 0.19.0 (Apache-2.0).
- New settings, all host-only and off or empty by default: `mcp_oauth_enabled`, `mcp_oauth_resource`,
  `mcp_oauth_dcr_enabled`, `mcp_oauth_cimd_hosts`, `mcp_oauth_rs_secret_hash`.
- New MCP server environment variables: `LOC_STUDIO_INPUT_DIRS`, `LOC_STUDIO_MAX_INPUT_BYTES`,
  `LOC_STUDIO_MCP_HUMAN_CONFIRM`, `LOC_STUDIO_MCP_TOOLSETS`, `LOC_STUDIO_MCP_SCOPE_FILTER`, and for
  MCP sign-in `LOC_STUDIO_MCP_OAUTH_RESOURCE`, `LOC_STUDIO_MCP_OAUTH_ISSUER` and
  `LOC_STUDIO_MCP_RS_SECRET`.
- Re-import older Word documents and Excel workbooks to pick up the new extraction (nested smart
  tags, text boxes). Existing documents keep exporting exactly as before.

## Known limitations

- Project automation: ownership of items across projects works for connectors that use the shared
  sync engine. Airtable, Jira, GitHub, GitLab and Bitbucket connections cannot feed a second project
  with the same scope, and full mode is not offered for them. A connection's own Translate now takes no
  ownership (the page warns). Each project bound to a shared connection reads the source system on its
  own schedule. A per-run spend cap can be exceeded by the calls already in progress when it is reached.
  A catch-up run after downtime runs at restart however old the missed slot is.
- Notifications: Slack uses incoming webhooks only. Teams delivery has not yet been tried against a
  live Teams tenant. Email channels can name any recipient (no domain allowlist yet). A workflow run
  that finishes or fails is not notified yet (a workflow run waiting for review is).
- Custom fields: multi-select and person fields are not available yet, and project templates do not
  carry field values.
- Most new connectors were tested against simulated vendor services; live checks against each
  vendor are completed as customer accounts come online. Drupal is experimental and depends on an
  alpha-stage Drupal module. CMS via MCP is a prototype.
- MCP sign-in has not yet been tried with claude.ai or ChatGPT connectors.
- Background MCP and API calls cannot be cancelled yet.
- Excel chart text and form-control text are not translated, and rich cells that mix formats
  lose their run formatting.
- Translated YAML, SSA/ASS and some INI files in a legacy code page are exported as UTF-8.
- Legacy binary Office files (.doc, .xls, .ppt), RTF, STAR Transit packages, Razor .cshtml and
  Outlook .msg are not supported.
- Check right-to-left InDesign exports in InDesign before delivery: the composer setting has not been
  confirmed in every InDesign version.
- Times are shown in UTC (the Automation page also shows your local time). Per-user time zones are
  planned.
