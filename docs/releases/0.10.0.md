# Localization OS 0.10.0

> Pre-open-source history. These notes describe a release from before Localization OS became open source; some features mentioned here (Advanced Workflows, evaluations, memory, Databricks export) are now paid add-ons and are not part of this repository.

Release date: October 8, 2026. Previous release: 0.9.5 (September 15, 2026).

Localization OS is an MT-first translation management system from Patois Labs. Release 0.10.0 is the
first official release since 0.9.5. It brings a new look, faster ways to find and fix work, finer
control over how machine translation speaks to your audience, much stronger sign-in and access
controls, and a long list of fidelity, reliability and security fixes.

## Highlights

1. **A new, calmer look.** One clean interface with Light, Dark or Match my computer, saved per
   account. Lists are simpler (search row, table, status dot, row menu), and confirmations use an
   in-app dialog instead of the browser's pop-up.
2. **Search everything from one box.** Global search covers projects, customers, documents,
   translation memory, glossaries, workflows and connections. Press Ctrl+K (Cmd+K on a Mac) anywhere
   to jump to a page or a result.
3. **Formality you can set.** Choose formal, informal or a language's own register (for example
   Sie or du, vous or tu, usted or tu) as a customer default, per project language, or per document.
   Machine translation, workflows, quality checks and reports all use the same choice.
4. **Repeated segments fill themselves.** Approving a segment copies the translation to its exact
   repeats in the same document, with Unlink and Undo, and never overwrites a person's edit or a
   locked segment.
5. **Workflows written once for every language.** Design a workflow without picking languages; the
   workflow page now has tabs (Steps, System prompt, Add a step), every prompt is locked until you
   unlock it, and Restore default is one click.
6. **Stronger sign-in and access.** Built-in two-step sign-in with an authenticator app and recovery
   codes, a configurable password policy, real account lockout, per-user API keys with optional
   expiry, and verified single sign-on account linking.
7. **AI opt-out per project and per customer.** When AI is off, this instance's AI engines never
   process that content. Content you download, export, or connect to your own AI tools (for example
   the MCP agent connection) is outside this switch.
8. **Better file fidelity.** Word documents keep pictures, charts, fields and links, and now translate
   headers, footers, footnotes, comments, text boxes, tracked insertions, nested tables and content
   controls. Translated files declare their language, and image alt text is translated.

## What's new by area

### Translation and AI

- **Formality** per customer, project language and document, with language-specific registers for
  German, French, Spanish, Italian, Dutch, Portuguese, Russian, Polish, Turkish, Swedish, Hindi,
  Japanese and Korean. "Auto" at any level means no instruction. The chosen register is recorded on
  each run.
- **Partial failures are failures.** A translation job, workflow run or image job where some segments
  or regions fail now ends as Failed with the engine's message, and export of the untranslated parts
  is held. A machine translation stream that is cut off counts as a failure and is retried.
- **Claude engine.** A refused request is quarantined for review instead of being written as a
  translation, and rate-limit waits follow the provider's Retry-After header (capped at 60 seconds).
  OpenAI and self-hosted engines flag refusals the same way.
- **Output guard.** Very short sources that come back as an echoed instruction or a much longer
  answer are held for review, and changed or dropped numbers are flagged.
- **Safer prompts.** Segment text is fenced inside prompts so short segments are not translated
  together with the instructions, and recalled project memory is passed as reference data only.
- **Self-hosted engines.** Explicit temperature and seed for repeatable output (judges run at
  temperature 0), optional model warm-up at run start, a per-engine limit on parallel translation
  jobs, and reused connections.
- **Traditional Chinese.** Google, Amazon and DeepL now return Traditional Chinese for zh-TW and
  zh-HK targets.
- **Quality estimation.** Jev (hosted, or a compatible self-hosted server) can be used as a quality
  judge, with an opt-in auto-fix loop of 1 to 5 rounds and an Inspect page with "Try it". A
  deterministic pre-check blocks untranslated text, dropped tags or placeholders, and changed
  numbers, dates, times, minus signs and currencies before the judge runs.
- **LQA.** Segments made only of numbers or punctuation that match the source are advisory, not a
  Major finding.
- **Run view.** Highlight differences between any two steps of a run, and see a step's full output.
- **Cost.** Each job stores the exact cost booked while it ran, and reports use it. Self-hosted
  engines on your own network are priced at zero. The pricing table was refreshed against current
  Google, OpenAI and Cohere price pages, and the default Gemini model moved to a current one.
- **Learned memory.** A learned term needs agreement from at least two people across two segments,
  and a style rule learned from LQA needs findings from at least two documents, before it is used.

### Editor and review

- Repeated-segment propagation on approve, with a Propagated badge, Unlink repeats and Undo.
- Approving a segment that dropped a placeholder or tag no longer writes it to translation memory
  unless you confirm, and the editor says why the memory write was held.
- While a workflow waits at a human review step, the editor shows the pending text read-only and
  links to the run, so edits cannot collide with the review.
- A "TM changed since fill" badge shows when the memory entry behind a segment was edited later; a
  re-run refreshes untouched machine-filled segments from the edited entry.
- The editor keeps a segment's state when you only move through it, the confirmed count survives a
  reload, and the live run page shows the final state when a run ends.
- Placeholder and tag-loss questions use an in-page dialog that works with screen readers.
- Clearer tag chips (g1, /g1, x1), fuzzy-match badges and match counts, and a compact layout.

### Terminology and translation memory

- Large TMX, glossary CSV and TBX imports write in short chunks, so other users are not blocked
  during a big import. A failed import can simply be run again: it finishes without duplicates.
- TM export streams instead of building one large file in memory; an empty glossary exports as a
  valid TBX file.
- TMX import and manual TM edits check placeholder integrity.
- Fuzzy scores of 99.5 and above no longer round up to an exact 100 match.
- Glossary pages are reorganized (Terms first, a clear path from draft to approved, per-pair
  editing). Re-importing a glossary keeps Do-Not-Translate flags when the cell is blank. Non-ASCII
  terms no longer match inside words.
- TM bulk delete on a customer's TM page stays within that customer.

### Workflows

- Language-agnostic workflows: design once, run for any language pair. Multilingual groups (per
  language variants) remain available under Advanced.
- Workflow page tabs: Steps, System prompt, Add a step and the prompt-authoring assistant, with one
  tab per step.
- The built-in system prompts can be viewed on the web, API, CLI and MCP. Org-level and per-workflow
  overrides are available behind an admin setting that is off by default.
- Locked prompts with Unlock, Apply, Lock again and Restore default; unapplied edits ask before you
  leave the page.
- Managers can edit a step's prompt and change a group's default workflow.
- Re-run and retry refuse archived workflows. A second, different workflow on the same document and
  language is refused while one is running.
- Correction-loop, Triage and Gated starting shapes draft working workflows.

### Admin and security

- Two-step sign-in (TOTP) for password accounts, with recovery codes; admins can require it for
  admins or for everyone.
- Password policy for local accounts (length, character classes, common-password block, history,
  optional maximum age).
- Account lockout after repeated failures, with admin unlock and an email to the user, and an
  optional trusted-network exemption for shared offices.
- Session timeout warning, an absolute session limit (default 24 hours), and sign-out everywhere on
  logout or password change.
- Per-user API keys with optional expiry and an organization-wide maximum age; per-key rate limits on
  spend and read routes.
- Single sign-on: OIDC accounts are linked to the provider's subject id after a verified email;
  SCIM deprovisioning and re-enabling are handled correctly.
- Department budgets hold across server processes, and Advanced Workflows runs respect project
  budgets.
- Prompt capture (the Ledger) prunes its oldest captures when it reaches its size budget and shows
  its retention status.
- Duplicate customer names are refused on create and rename.

### Integrations, API, CLI and MCP

- Every new feature is available on the web, the API, the CLI and the MCP server.
- The MCP server runs on MCP 2.x, with per-client session limits.
- Connector fixes: no duplicate Airtable records on retry, WordPress posts are not orphaned by a
  temporary error, Intercom drafts no longer unpublish a live locale, Notion targets are not cleared
  before a rejected append, Jira and Airtable pending queues are kept when a run fails, and fetches
  stop at the document and byte caps.
- The remote CLI reads its key from a file or environment variable, refuses plain http to public
  hosts, and reports failures with a non-zero exit code.
- API input handling is stricter and clearer: unknown customers answer 404, duplicate names 409,
  empty uploads 422, non-object JSON bodies 400, and status changes follow the allowed transitions.
- Legacy-encoded text uploads (for example Windows-1252) are converted automatically; translations
  export as UTF-8.

### Accessibility

- Broad accessibility work toward WCAG 2.2 AA: contrast and 24 px targets, reflow at 320 px,
  landmarks and labels, an error summary on forms, language of parts on source and target text,
  keyboard alternatives to dragging, screen reader announcements in the editor and run view, and a
  session timeout warning.
- An accessibility contact can be set and is shown in Help.
- Editable page layouts: each person can arrange the cards on a page type, saved to their account.

### Look and feel

- The Console look: one light and dark theme, Public Sans and JetBrains Mono, a single accent color,
  hairline borders and centered content on list and settings pages.
- Theme and "Get started" are in the account menu.
- Busy indicators on every action that does work, with an elapsed counter on slow AI actions.
- Themed "not found" pages, upload errors shown on the form, and export refusals explained in a
  dialog with next steps.

## Security and compliance improvements

This release closes the findings of two internal security reviews (September and October 2026) and an
internal penetration test. The main changes:

- **Access control.** Organization, customer and project boundaries are checked first on every web,
  API, CLI and MCP route, so a hidden item answers exactly like a missing one. Many role gaps were
  closed (for example, engine and connector credentials can no longer be redirected by a non-admin).
- **Sign-in.** Two-step sign-in, account lockout, password policy, a one-time setup token for the
  first administrator on a server install, session invalidation on logout, and stricter single
  sign-on linking.
- **Browser protections.** An enforced script Content Security Policy with per-request nonces,
  removal of inline event handlers, and fixes for stored cross-site scripting findings.
- **Outbound requests.** Every outbound client goes through the same network guard, which resolves a
  host once, checks every address and connects only to the checked address (DNS rebinding
  protection).
- **Abuse resistance.** Request body size caps, per-document segment, character and row caps,
  decompression and pixel limits for documents and images, and linear-time text checks so a single
  hostile input cannot stall the server.
- **Audit log.** Audit writes fail closed (a request whose audit record cannot be written is
  refused), the hash chain detects deleted or edited rows, and audit verification runs faster.
- **Privacy.** AI opt-out, PII redaction coverage on more AI paths, erasure that reaches learned
  memories, TM rows, exports and evaluation snapshots, and retention that skips in-flight work.
- **Supply chain.** Hash-pinned Python dependency locks, base images pinned by digest, no pip in the
  runtime image, a CycloneDX SBOM of the locked Python packages, and an image vulnerability scan gate
  in the deployment instructions.
- **LDAP.** The directory server's certificate is validated and cleartext binds are refused.

These are engineering controls. This release does not claim any third-party certification.

## Changed or removed

- **Skins removed.** The Default, Instrument and Ledger skins are replaced by one look with Light,
  Dark or Match my computer per account. Removed: the skin picker, `POST /account/skin`,
  `POST /api/account/skin`, the `skin` field of `GET /api/account` and `account set-skin`. New:
  `ui_theme` on `GET /api/account`, `POST /api/account/theme` and `account set-theme`.
- **Back-office console and super-admin account removed.** Organization lifecycle (create, rename,
  suspend, delete) is done from the command line on the host with the operator key.
- **Shared connector token removed.** Integrations use per-user API keys. The MCP HTTP server no
  longer uses its own token for requests that send none.
- **`/health` is minimal.** It returns only the status and the major.minor version. Use
  `/api/release` (authenticated) or `version` on the CLI for the exact release.
- **Workflows without a group carry no language pair.** An inert pair stored on such workflows is
  cleared once during the upgrade.
- **Failures are reported as failures.** Jobs and runs with failed segments or image regions end as
  Failed instead of Completed.
- **Hidden and missing items look the same.** Routes answer 404 for both.
- **Fuzzy match rounding.** Scores of 99.5 to 99.99 stay fuzzy.
- **Default Gemini model** changed from a retired model to a current one.

## Upgrade notes for self-hosted installs

Follow the Upgrade section of the deployment guide (DEPLOY): stop writers, take and verify a full checkpoint with
the old image, build from the release tag, then migrate. Downgrade is by restoring the checkpoint;
never run an old image against the new schema.

**Database migrations.** Twenty new migrations, applied by `db migrate` (or the container
entrypoint) to a single head, `e4a7c2b9d1f6`. They add: user session epoch, login throttle, two-step
sign-in, password policy, AI opt-out, TM retention activity, page layouts, Jev auto-fix columns, the
upload blob identity and blob delete outbox, audit log organization, system prompt overrides (org
and workflow), API key expiry, job cost, assistant allowance, OIDC subject binding, MT formality and
user theme. One is data-only and not reversible: it clears the inert language pair on workflows
that are not in a group.

**First boot after the upgrade.**

- Everyone signs in again once (sessions now carry a per-user epoch).
- A server install with no accounts asks for a one-time setup token on `/auth/setup`. It is printed
  in the startup log and stored in `.setup_token` in the data folder, or set `LOC_TMS_SETUP_TOKEN`
  (at least 16 characters). There are no default `admin/admin` credentials on a server install.
- The session secret must be at least 16 characters; an empty or short secret stops startup.
- A legacy install with `encrypt_db=1` and no SQLCipher refuses to start. Run
  `config set encrypt_db 0 --yes` locally to continue in plaintext, or convert to SQLCipher as
  described in the secrets guide (SECRETS).
- LDAP: the server certificate must validate. Use `ldaps://` or StartTLS with a DNS name; for an
  internal CA set `ldap_ca_cert`. Cleartext binds and IP-literal hosts are refused.
  `admin ldap test-login` reports the reason.
- OIDC: an existing account links to the provider on its next sign-in with a verified email. If your
  provider never sends `email_verified` (Microsoft Entra ID by default), those sign-ins are refused
  until an admin turns on "Trust this provider's email addresses" on the Security page (use only with
  a single-tenant provider).
- Test mode now needs both `LOC_TMS_DATA_DIR` and `LOC_TMS_TEST_MODE=1` on a loopback address.
  `LOC_TMS_DATA_DIR` alone is a real install with the login wall.
- Any account flagged as super-admin is cleared once at boot (the flag no longer grants anything).

**Environment.**

- New: `LOC_TMS_SETUP_TOKEN` (first administrator), `LOC_TMS_CSP_MODE` (`enforce` by default,
  `report-only` or `off`), `LOC_TMS_TEST_MODE`, `LOC_TMS_TOKEN` (remote CLI key),
  `LOC_TMS_PII_INSTITUTION_ID_DIGITS` (default 8), `LOC_TMS_GIL_SWITCH_INTERVAL_S` (advanced), and
  `VSTUDIO_TRUSTED_PROXY_IPS` for Vendor Studio behind a proxy.
- Removed: `LOC_TMS_BACKOFFICE_SECRET`.
- `LOC_TMS_JOB_WORKERS` (default 2) is the global cap on background jobs. The new per-engine
  `max_parallel_jobs` only lowers it, so raise `LOC_TMS_JOB_WORKERS` first if an engine can run more
  jobs at once. Each extra worker adds CPU load on the server.
- Client IP headers are trusted only from the proxies listed in `trusted_proxy_ips`.

**Dependencies.**

- Python 3.13 is the version the image, CI and test runner use; use 3.13 for host installs.
- Major jumps: `anthropic` 0.42.0 to 1.11.0 and `mcp` 1.29.0 to 2.3.0. Also `fastapi` 0.142.2,
  `starlette` 1.7.0, `uvicorn` 0.54.0, `alembic` 1.20.0, `sqlmodel` 0.0.44, `google-genai` 2.28.0,
  `PyJWT` 2.15.1 and `urllib3` 2.8.0. New: `httpx2`, `httpcore2`, `truststore`, `mcp-types`,
  `opentelemetry-api`, `segno` (QR codes for two-step sign-in) and `docstring-parser`. Removed:
  `httpx-sse` and `pydantic-settings`.
- Locks are hash-pinned: install with `pip install --require-hashes -r requirements.lock` (plus the
  profile locks you use).
- The container runs as a non-root user with read-only application code and no pip at runtime. Base
  images are pinned by digest.

## Known limitations

- Times are shown in UTC. Per-user time zones are planned.
- Running several organizations on one install (multi-org) stays off and is not supported for
  production use in this release.
- An OIDC account link cannot yet be removed by an admin from the app.
- A few page-specific confirmations still use the browser's own dialog.
- Imports larger than 2,500 rows commit in chunks: if one fails partway, the rows already written
  stay. Running the same import again completes it without duplicates. Concept-preserving glossary
  JSON import still runs as one transaction.
- Gemini refusals are not yet detected by the refusal quarantine (Claude, OpenAI and self-hosted
  engines are).
- The container image bundles Tailscale binaries that carry upstream advisories (Go `x/crypto` and
  `x/image`); they are updated when a fixed upstream release ships. The Tailscale sidecar runs only
  when you configure a tailnet.
